# Synchronisation Strategies

- Synchronisation
	- determining an event order
	  确定事件顺序
	- used for
		- moving a signal into a clock domain
		  将信号移动到时钟域
		- Asynchronous arbitration
		  异步仲裁
- Failure Probability
	- is proportional to fraction of *vulnerable* time
	  与**易受影响**时间的比例成正比
	- exponentially decreases with waiting period
	  随等待时间呈指数下降
	- exponentially increases with flip-flop time constant
	  随触发器时间常数呈指数增加
	- failure rate is proportional to event rate
	  失败率与事件速率成正比
- Synchronisation Failure
	- as the time between two signals decreases, it becomes more difficult to tell which came first
	  随着两个信号之间的时间间隔减少，判断哪个信号先到变得更加困难
	- Synchroniser may hang in a meta-stable state, unable to decide
	  同步器可能会陷入亚稳态，无法做出决定

## What is Synchronisation

- A synchroniser determines the order of events on two signals
  同步器确定两个信号的事件顺序
- Which event came first?
  哪个事件先发生？
	- Does it matter?
	  影响大吗？
	- Sometimes synchronisation is unnecessary
	  有时候同步并不必要
- Often one signal is a clock
  通常其中一个信号是时钟
	- Did the data go high before or after the clock went high?
	  数据是在时钟变高之前还是之后变高的？
- Why is this problem hard?

## Applications of Synchronisation

- Sampling asynchronous inputs with a clock
  采用时钟对异步输入进行采样
	- Particle counter or pushbutton
	  粒子计数器或按钮开关
- Crossing clock domains
  跨时钟域
	- Sampling a synchronous signal with a different clock
	  采用不同时钟对同步信号进行采样
	- this is an easier problem if both clocks are periodic
	  如果两个时钟都是周期性的，该问题会更容易处理
- Arbitration of asynchronous signals
  异步信号的仲裁
	- Request line for shared resources
	  共享资源的请求信号
	- Game-show pushbutton
	  竞赛节目中的抢答按钮

## Synchronisation Failure

- Which came first, event on $A$ or event on $B$?
  是事件 $A$ 先发生，还是事件 $B$ 先发生？
- The closer the race, the harder it is to decide
  事件发生的时间间隔越接近，判断先后顺序越困难
- When the events are very close, the synchroniser may take an arbitrary amount of time to exit this state
  当事件非常接近时，同步器可能需要任意长的时间才能脱离这种状态
- Synchroniser output may be interpreted inconsistently in the meantime
  在此期间，同步器的输出可能被不一致地解释

## A NAND Arbiter
*NAND仲裁器*

![[Pasted image 20250501152538.png#pic_50center|]]
- Consider a NAND SR Latch
- We can attempt to use this as an arbiter
  我们可以尝试将其用作仲裁器
	- If $A$ arrives much earlier than $B$, $Afirst^\prime$ goes low and locks $B$ out.
	  如果 $A$ 远早于 $B$ 到达，则 $Afirst^\prime$ 变低并锁定 $B$
	- If $B$ arrives much earlier than $A$, $Bfirst^\prime$ goes low and locks $A$ out.
	  如果 $B$ 远早于 $A$ 到达，则 $Bfirst^\prime$ 变低并锁定 $A$
- What happens if A and B go high at nearly the same time?

![[Pasted image 20250501180152.png#pic_50center|]]
- When $A$ and $B$ go high at nearly the same time, difference in output voltage is proportional to the difference in time (Initial Voltage)
  当 $A$ 和 $B$ 几乎同时变高时，输出电压的差值与时间差成正比$$\Delta V_1=K_s\Delta t$$
- When $A$ and $B$ go high, initial voltage difference is exponentially amplified (Exponential Regeneration)
  当 $A$ 和 $B$ 变高时，初始电压差会呈指数级放大$$\Delta V(t)=\Delta V_1 \mathrm{exp}\left(\frac{t}{\tau_s}\right)$$其中$\tau_s$是Regeneration Time Constant
- Dynamics Settling Time: 假设$\Delta V$最终为$1V$，那么综合上面两个式子可以得到$$t_x=-\tau_s\mathrm{ln}(K_s\Delta t)$$其中$t_x$就是Dynamics Settling Time

### Calculating Synchronisation Failure

![[Pasted image 20250501180343.png#pic_50center|]]
$$P(\text{failure})=P(\text{enter meta-stable state})\times P(\text{still in state after }t_w)$$

![[Pasted image 20250501180839.png#pic_75center|]]
- Probability of Entering into the Meta-stable State: 
	- FF1 may enter the meta-stable state if the input signal transitions during the aperture time ($t_a$) of the flip flop.
	  如果输入信号在触发器的孔径时间 ($t_a$) 内发生跳变，FF1 可能进入亚稳态
	- Probability of a given transition being in the aperture time is the fraction of time that is aperture time
	  这个概率是孔径时间在整个周期时间中的占比：$$P_e=\frac{t_a}{t_{cy}}=f_{cy}t_a$$

![[Pasted image 20250501183001.png#pic_75center|]]
- Probability of Staying in the Meta-stable state
	- Still in meta-stable state if initial voltage difference was too small to be exponentially amplified during wait time
	  如果初始电压差过小，在等待时间内无法被指数级放大，则仍处于亚稳态
	- Probability of starting with this voltage is proportion of total voltage range that is 'too small'
	  进入该状态的概率取决于总电压范围中“过小”部分所占的比例$$\displaylines{\Delta V_s=\Delta V_F\cdot\mathrm{exp}\left(-\frac{t_w}{\tau_s}\right) \\ P_s=\frac{\Delta V_s}{\Delta V_F}=\mathrm{exp}\left(-\frac{t_w}{\tau_s}\right)}$$

## Failure Probability and Error Rate

- Each event can potentially fail$$P_f=P_eP_s=t_af_{cy}\mathrm{exp}\left(-\frac{t_w}{\tau_s}\right)$$
- Failure rate is given by the $\text{event rate} \times \text{the failure probability}$ $$f_f=f_e\cdot P_f=f_et_af_{cy}\mathrm{exp}\left(-\frac{t_w}{\tau_s}\right)$$
  $f_e$是事件发生的频率Event Rate

## 例子

- Assume a Brute-force synchroniser with a 500MHz clock samples a 10MHz asynchronous input signal
- The flip-flops have aperture time ($t_a$) and regeneration time ($\tau_s$) of 100ps
- What is the probability of synchronisation failure ($P_f$)?
- What is the frequency of synchronisation failure ($f_f$)?
- What is the mean time between synchronisation failures (MTBF)?

$$t_{cy}=\frac{1}{500\mathrm{MHz}}=2\mathrm{nS}$$
$$P_f=\frac{t_a}{t_{cy}}\cdot\mathrm{exp}\left(-\frac{t_{w}}{\tau_s}\right)=1.031\times10^{-10}$$
$$f_f=f_e\times P_f=10\mathrm{MHz}\times1.031\times 10^{-10}=1.031\times10^{-3}\mathrm{Hz}$$
$$\mathrm{MTBF}=\frac{1}{f_f}=969.9\mathrm{S}$$

## Synchronisation Hierarchy

- The difficulty of synchronisation depends on the relationship between events on the signal and events on the clock
  同步的难度取决于信号事件与时钟事件之间的关系
- Synchronous
  同步
	- Signal events always happen outside of the clock's keep-out region
	  信号事件始终发生在时钟的避让区域之外
		- same clock
- Mesochronous
  均步
	- Signals events happen with a fixes but unknown phase relative to the clock
	  信号事件相对于时钟具有固定但未知的相位
		- same frequency clock
- Plesiochronous
  准同步
	- Phase of signal events changes slowly with time
		- Slightly different frequency clock
- Periodic
  周期
	- Signal events are periodic
	  信号是任意频率的周期信号，信号事件的周期性可以用来提前预测哪些信号会发生在时钟的不可靠部分内。
		- Includes meso- and plesiochrounous
		- signal is synchronised to some periodic clock
- Asychronous
	- Signal events may occur at any time

## Mesochronous Synchronisation

![[Pasted image 20250501191033.png#pic_75center|]]
- The phase difference between the signal and the clock is constant
  信号与时钟之间的相位差是恒定的
	- typical of systems where we distribute a master clock with some degree of clock skew
	  这通常出现在我们分配主时钟并存在一定时钟偏移的系统中
- Thus, we only need to synchronise once for all time!
  因此，我们只需进行一次同步，即可长期保持同步！
- During reset check the phase
  在复位过程中检查相位
	- if it’s OK, sample the signal directly forever
	  如果相位正确，则可以永久直接采样信号
	- if it’s not, sample the signal after delay forever
	  如果相位不正确，则需要永久延迟采样信号
	- this phase check is the only asynchronous event we ever sample and we can afford to wait a long time
	  这次相位检查是唯一需要采样的异步事件，我们可以等待较长时间来确保其稳定性

### Detecting an Unsafe Signal

![[Pasted image 20250501195653.png#pic_75center|]]
![[Pasted image 20250501200216.png#pic_25center|]]
- To see if a signal is unsafe, see if it changes in the forbidden region
  判断信号是否不安全的方法是观察它是否在禁止区域内发生变化
- sample just before and after the forbidden region and see if result is different
  在禁止区域之前和之后进行采样，并比较结果是否不同

### Plesiochronous Timing

- With plesiochronous timing, one clock is running slightly faster than the other
	- e.g., system with independent crystal oscillators with same nominal frequency (±200ppm)
	  例如，具有名义上相同频率（±200ppm）的独立晶振系统
- The same basic synchroniser types apply
	- brute force
	- delay line
	- two-register
	- FIFO
- We need to re-synchronise periodically
	- e.g., once every 1,000 clocks
- We need flow control
	- have to match data rate of tx and rx even if clock rate is different
	  即使时钟速率不同，也必须匹配发送（tx）和接收（rx）的数据速率
	- eventually the phase wraps and we either get 2 or 0 data elements during a particular clock
	  随着相位变化，可能在某个时钟周期内得到两个数据元素或零个数据元素
	- unless we make sure we are not sending data when the phase wraps
	  除非确保在相位变化时不发送数据，否则可能出现数据不稳定的情况

## Periodic Timing

- Transmit and receive clocks are periodic but at unrelated frequencies
  发送和接收时钟是周期性的，但频率无关
	- e.g., modules in a system clocked by separate oscillators with independent frequencies
	  例如，系统中的模块由独立频率的单独振荡器驱动
	- case where one is rationally derived from the other is an interesting special case
	  一种情况是从另一种情况中理性推导出来的，这是一个有趣的特例
- In this situation, a single synchronisation won't last forever (like mesochronous) or even for a long time (like plesiochronous)
  在这种情况下，单次同步不会持续永久（像均步同步），甚至不会持续很长时间（准同步）
- However, we can still look into the future and predict clock conflicts far enough ahead to reduce synchroniser delay
  但是，我们仍然可以预测未来的时钟冲突，并提前调整，以减少同步器的延迟


## Periodic Synchroniser

![[Pasted image 20250501202256.png#pic_75center|]]
- If an input signal is synchronised to some periodic clock, we can predict when its events are allowed to happen arbitrarily far into the future
  如果输入信号与某个周期性时钟同步，我们可以预测其事件在未来任意时刻发生的可能性
- Thus, we can determine well in advance if the signal is safe to sample on a given clock cycle
  因此，我们可以提前判断信号在某个时钟周期内是否可以安全采样
	- if it is, we just sample it
	  如果安全，则直接采样
	- if it isn’t, we delay the signal (or the clock) to make it safe
	  如果不安全，则延迟信号（或时钟）以确保安全
- This allows us to move the waiting time, $t_w$ , out of the critical path.
  这使我们可以将等待时间 $t_w$ 移出关键路径
	- we can make it very long without adding latency
	  可以使其非常长，而不会增加延迟

# Asynchroniser Design

- Asynchronous design
	- most synchronisation is unnecessary
	  大多数同步是不必要的
	- can be avoided by using asynchronous design
	  通过异步设计可以避免同步需求
- A stoppable clock
	- stop clock between events
	  在事件之间停止时钟
	- start clock when an input event occurs
	  当输入事件发生时启动时钟
- Combination asynchronous modules
	- inputs and outputs encode events not just values (but also timing)
	  输入和输出不仅编码数值，还编码事件的时间信息
	- modules obey the weak conditions
	  模块满足弱条件
		- number of events on each output is equal to or less than the number of events on each input
		  每个输出上的事件数小于或等于每个输入上的事件数
		  > 弱条件即允许在所有输入还没有被完全定义（只存在部分输入）时存在输出
- Composition
	- weak conditions are closed under acyclic composition
	  弱条件在非循环组合下保持成立

- Most often we synchronise just an event to a clock
  通常我们只是将一个事件与时钟同步
	- It doesn’t matter if we handle the event on clock $i$ or $i+1$
	  事件在时钟 $i$ 或 $i+1$ 上处理并无影响
- We can avoid this unnecessary synchronization by processing events asynchronously
  通过异步处理事件可以避免不必要的同步
- The arrival of an event triggers its handling
  事件的到达会触发其处理

## Asynchronous Circuits Design and Verifications

- The Weak Conditions - A constraint on input and output events
  弱条件 - 对输入和输出事件的约束
- Inputs and outputs transition in the following order
  弱条件下的输入输出约束
	1. some input(s) become valid
	   一些输入可用
	2. some output(s) become valid
	   一些输出可用
	3. all inputs become valid
	   所有输入可用
	4. all outputs become valid
	   所有输出可用
	5. some input(s) become invalid
	   一些输入不可用
	6. some output(s) become invalid
	   一些输出不可用
	7. all inputs become invalid
	   所有输出不可用
	8. all outputs become invalid
	   所有输出不可用
- So, for example it is not allowed for
	- any output to become valid before any input becomes valid
	  任何输出在任何输入变得有效之前变得有效
	- all outputs to become valid while any input is invalid
	  在任何输入无效时，所有输出都变得有效
	- any output to become invalid while all inputs are valid
