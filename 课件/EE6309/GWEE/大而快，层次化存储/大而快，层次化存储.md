## 术语

- MAR: Memory address register
- MBR: Memory buffer register
- MDR: Memory data register
- Word: The “natural” unit of organization of memory. Common word lengths are 8, 16, and 32 bits.
  字长一般是内存和处理器处理数据的最小单位（也可能不是），而且长度是不定的（甚至可能不同于总线位宽或者处理器位数），所以如果有题目没有明确说明字长是多长，建议去抽他大嘴巴子。
- Memory cycle: When CPU needs to read a word from memory, either an instruction or data, it loads the address of the word it wants into the MAR and sends a read signal to the memory. After one memory cycle, the memory puts the desired word in the MBR where the CPU can take it out and use it.
  所以Memory Cycle就是CPU将地址放进MAR后，到MBR数据可用的时间。书上对这块分得更细，但在Gwee的世界观下Memory Cycle Time和Access Times相同，舍去了额外的延迟。
- Meta bit (tag bit, valid bit, flag bit): It is an extra bit associated with each cell (or location) to indicate its content. e.g. 0 for instruction, 1 for data. It can also be used to distinguish the data type, for example, floating point numbers or integers etc.
  用来做标记的乱七八糟的小玩意
- Reference: 内存引用，内存访问

# 内存交织

## Bank

*实际上这里并不是垃圾佬捡内存条时遇到的那个Bank*

这里很单纯就是一组排列好的，能够被寻址的内存单元。按照这门课的惯例，一个地址对应一个word

## High Order Interleave

![[Pasted image 20250412184501.png#pic_75center|High Order Interleave]]

- 地址结构：$\text{<Bank Select> <Address within the selected bank>}$

If the CPU and I/O devices use different banks of memory for their instruction and data, all the banks can be accessed simultaneously with different ports and buses. In this manner, the overall speed performance of the computer can be effectively increased.

如果 CPU 和 I/O 设备分别使用不同的内存bank来存储指令和数据，那么所有的内存bank可以通过不同的端口和总线同时访问。通过这种方式，计算机的整体速度性能可以得到有效提高。（比较像哈佛结构）

### 例子

In certain pipeline processing systems, instructions and operands are placed in two different modules (banks) to enable the parallel processing (overlapping) of the instruction fetch cycle and the reading of the operand.
在某些流水线处理系统中，指令和操作数被放置在两个不同的内存bank中，以实现指令取周期和操作数读取的并行处理（重叠处理）

## Low Order Interleave

![[Pasted image 20250412185446.png#pic_75center|]]

- 地址结构：$\text{<Address within the selected bank> <Bank Select>}$

In this configuration, consecutive addresses are in alternate banks such that each device (CPU or I/O) will need to access all the banks in order to execute instructions or data. The computer can overlap consecutive memory accesses. After the CPU has requested access to the first word in bank 1, it can move to bank 2 while the memory management unit is still waiting for the retrieval of the first word in bank 1. The CPU continues in this manner from one bank to the next. By the time the CPU returns to bank 1, the retrieval of the first word in bank 1 should be completed and the retrieval of the next word in bank 1 can be initiated. In this manner, the memory access can be greatly speeded up to the speed of the CPU.

在这种配置中，连续的地址会分布在交替的内存bank中，因此每个设备（CPU 或 I/O）都需要访问所有的内存bank才能执行指令或数据。计算机可以重叠连续的内存访问。当 CPU 请求访问内存bank 1 中的第一个字时，它可以转向内存bank 2，而内存管理单元仍在等待从内存bank 1 中检索第一个字。CPU 以这种方式从一个内存bank继续到下一个。当 CPU 返回到内存bank 1 时，内存bank 1 中第一个字的检索应该已经完成，并且可以启动对内存bank 1 中下一个字的检索。通过这种方式，内存访问的速度可以大大加快，达到与 CPU 的速度相匹配的程度。（类似流水线，提高了吞吐量）

### 例子

CPU频率200M，内存访问时间50nS

CPU时钟周期5nS，所以要10个内存bank流水线Low Order Interleave来达到CPU的吞吐量。

# 层次化存储

- The part of the operating system that supervises the flow of information between all storage devices is called the memory management unit (MMU).
- The objective of a MMU is to minimize the cost per bit of storage for a given performance requirement.
- This objective of a MMU is normally achieved by using a hierarchical memory, which consists of several levels of different types of memories of different speeds and costs.
- The function of a MMU is therefore to adjust the frequency with which the various memories in the hierarchy are referenced (accessed) to provide an efficient method of data transfer between these memories so as to maximize the utilization of all computer components with respect to speed and cost.

## 二级存储

- Let $t_{\text{A1}}$ and $t_{\text{A2}}$ be the system access times to $M_1$ (main Memory) and $M_2$ (Secondary memory) for a reference respectively. The average system access time for a word is: $$\begin{align}\displaylines{t_{\text{A}}=& Ht_{\text{A1}}+(1-H)t_{\text{A2}} \\ t_{\text{A1}}=& t_{\text{M1}} \\ t_{\text{A2}}=& t_{\text{B}}+t_{\text{A1}} \\ t_{\text{B}}=& b_s\times t_{\text{M2}}}\end{align}$$
  where:
	- $H$: Hit ratio
	- $t_{\text{B}}$: Block transfer times from $M_2$ to $M_1$
	- $b_s$: Block size

稍作推理（打开$t_{\text{B}}$），假设$\text{Block Size}=1\text{Word}$，能够得到：$$t_{\text{A}}=t_{\text{M1}}+\left(1-H\right)t_{\text{M2}}$$

## Access Efficiency

定义：$$e=\frac{t_{\text{A1}}}{t_{\text{A}}}=\frac{1}{H+(1-H)\frac{t_{\text{A2}}}{t_{\text{A1}}}}$$

# 相联存储器 Associative Memory

- Concept : The time required to find an item (data or instruction) in a memory can be reduced considerably if the stored item can be identified for access by content instead of by its address.
- 一种随机存储器，它允许对一个Word中的指定bit（通过Key Register进行掩码）进行检查匹配，能够同时在所有Word中进行。因此，这货是通过它的内容而不是地址进行检索。

- This type of memory is known as Content Addressable Memory (CAM).
- Memory cells in a CAM are accessed simultaneously within **one memory cycle** on the basis of data content rather than by a specific address or location to obtain the data required.
  所有单元都在一个周期内并行访问，查找数据基于的是数据的内容而不是地址。
- The search for the required data in the memory can be done on the entire word or on a specific field within a word.
- It is more expensive than a normal memory as each cell must be equipped with storage capability as well as logic circuits for matching its content with an external argument.
  很贵，要搭载额外的逻辑电路
- It is used mostly in applications where the search time is very critical.
- Applications: Password or Image Matching

# 虚拟存储

由于每个程序直接在裸的物理内存上跑非常不现实（各种入口处理非常困难），所以聪明的大聪明们弄出了虚拟存储。

在单个应用看来，自己的**内存空间都是连续的**，即使这些内存在实际的物理内存中并不连续。操作系统和MMU通过重定向共同创造了这个虚拟的世界，让应用以为自己在一段连续的内存中，从而世界大同。

虚拟的内存空间可以远比物理内存大，碎片化的组织也可以尽可能地利用实际的物理内存。当然了，具体的实现过程取决于不同的CPU和不同的操作系统。将虚拟地址转化为物理地址的过程被称为地址的翻译（Translate）

## 术语

- **Virtual address**: An address used by a programmer for a program. It is also known as a **logical address**.
- **Address space**: It refers to the virtual address space. It is also known as **name space**.
- **Physical address**: An address in main memory (or physical memory). It is also known as **real address**
- **Memory space**: It refers to the main memory address space.


## 直接映射

*没见过什么书讲这个*

- The address space of a program is divided into smaller sizes of address spaces each of which is not greater than the main memory size.
  程序的Address Space被划分为更小的Address Space，每个Address Space的大小均不大于Main Memory的大小。
- 因为虚拟内存中地址空间的大小是能够超过Main Memory的大小的，为了保证运行中不会出错（超出Main Memory的范围导致爆炸），所以需要将虚拟的内存空间分解成一块一块不大于Main Memory的部分。要用的时候就会从硬盘中读取塞满Main Memory，用完了就继续从硬盘读。

- 在上图中，虚拟的地址空间达到了64K，而Main Memory只有4K. 所以直接映射中每一段不能超过4K

## 页

- 这是一种在存储器中使用的技术，通过将存储器分成大小相同的部分来执行碎片化管理。在虚拟地址空间的部分被称为页（Page），在物理地址空间的部分被称为帧（Frame）或者块（Block）。

![[Pasted image 20250412211551.png#pic_50center|空闲的内存塞不进更多的进程了！]]

- 在页出现之前，大聪明们对内存的管理是连续的，每个进程享有一段独立且连续的分区，但是当空闲的空间不足以继续连续分配内存后，就无法加载更多的进程了。

![[Pasted image 20250412211627.png#pic_50center|页能够充分利用内存的碎片空间]]

- 所以大聪明们将这些分区继续打碎变成更小的部分，建立起逻辑地址到物理地址的映射。即每一个页（Page）都对应一个帧（Page Frame），自然地，页和帧的大小也是相同的。
- 在分配内存时，使用分页能够保证内存的浪费少于1个页的大小，那么平均一下就是1/2个页的容量可能会被浪费。大大小于以前的浪费。

### 页的映射

- 既然内存已经虚拟化了，那么就必须进行虚拟到现实的翻译，处理这一过程需要将页映射到帧中。

#### 页表映射

最常用的办法是使用一个页表来管理每个页应该映射到哪一个帧上。

![[Pasted image 20250412212658.png#pic_50center|]]

- 在应用的虚拟地址中，为了处理映射关系，需要将地址分为两段。这也就是一般大家经常说的页号和页内地址。
- 这一切也是为了尽可能让应用运行时看到的逻辑地址是连续的。也就是说并不是我们将页号和页内地址组合成了逻辑地址，而是将本来连续分布的逻辑地址拆分开来。
- 页表存储在哪呢？根据后面的PPT，我们不难推测出页表其实是主存中一个特殊的地方，这地方不对用户代码开放，而由操作系统管理。

### 页替换

- 当被引用的页不在主存中时，会发生缺页失效（Page Fault）。如果主存满了，就需要进行页替换以将更新的页写入主存。
- 页替换算法的主要目的是将最不可能即将被引用的页替换。

#### First-In-First-Out (FIFO)

- FIFO算法每次替换都会把最老的页替换为最新的页。

- 这种算法很容易想到一个FIFO队列来实现，但实际在内存中是没有队列这种方便的东西的，所以操作系统必须随时保存最老的那一页的位置，以便发生替换时能够找到（自己实现队列）。在顺序的内存中使用“$*$”星号来表示最老的那一页。

- 当然了，如果出的题没有说明白哪一头是最老的，要抽出题人大耳刮子（比如告诉你页表是1234，但是不说最老的是1还是4）

#### Least Frequency Used (LFU)

- It selects for replacement the page that it has been least frequently referenced.
- 如果两个页的访问频率相同怎么办？根据贪心的原则，我们可以找更老的那个页进行替换。
- 如果我们用一个结构（页号，引用次数，最近引用时间）来存储页表项，那么我们只需要找到最少引用和在相同次数时最老引用的那一项替换就行，并且在每次命中时更新频率和引用时间。

#### Optimal Replacement Policy (OPT)

- It is an optimal replacement policy. The page to be replaced is the one that will have the longest page fault interval.
- This is equivalent to determine at time $T$, the time $T_j$ at which the next reference to the same page occurs. The page with the biggest $T_j$ is to be replaced.
- OPT requires the page address stream in advance before execution. Therefore, implementation of OPT requires two passes through the program. The first is a simulation run to determine the page address sequence. The second is the execution run. OPT is not practically feasible because of the cost of the simulation run and the page address stream may be very long, and the fact that in some situations such as those in a real time system, the page stream may be dependent on external events.
  OPT（最优页面置换算法）在执行之前需要提前获取页面地址流。因此，实施 OPT 需要对程序进行两次运行。第一次是模拟运行，用于确定页面地址序列。第二次是正式执行运行。由于模拟运行的成本较高，页面地址流可能非常长，并且在某些情况下（例如实时系统中），页面地址流可能依赖于外部事件，因此 OPT 实际上并不可行。、

#### 栈算法

- 在缺页替换算法中，会产生一种现象叫做Belady异常。比如FIFO算法导致的，虽然页增多了但是命中率并没有提升的现象。
- 如何避免Belady现象：某一时刻，空间为$n$的页表需要是空间为$n+1$页表的子集
- 理解：如果空间为$n$的页表在某一特定时刻恰好缺页，那么空间为$n+1$的页表在此时一定不会缺页。反过来思考，容量为$n+1$的页表缺页次数一定比容量为$n$的少，从而避免了Belady现象。（我抄的，我数学烂）

- 公式化表述：$$\begin{align} \left \{\displaylines{B_{(t)}\left(n\right)\subset B_{(t)}\left(n+1\right),\quad n<L_{(t)} \\ B_{(t)}\left(n\right)=B_{(t)}\left(n+1\right),\quad n\geq L_{(t)}} \right .\end{align}$$
  其中：
	- $n$是页表的容量
	- $B_{(t)}\left(n\right)$是某一时刻$t$，容量为$n$的页表中元素组成的集合
	- $L_{(t)}$是直到某一时刻$t$，遇到的不同的页的次数

## 段

*Segmentation Error（*

- 页的存在固然大大提高了虚拟存储管理的效率，但假设有一个情况：有一段代码包含了两个同样的过程（过程是一个计算机概念，可以认为是子程序）。从效率最高的做法出发，我们应该给这个过程设计一个入口，每次调用都从这个入口进入。这样只需要一段内存就能让两个地方使用这个过程。当然了，这么好的事没法直接达成，即使我们有了页这一工具也做不到。
- 所以大聪明们发明了段，段包含了一大堆页，从而实现了更高层级的抽象，更高的难度和更高的效率。很显然，我们的抽象层级正在逐渐提高。

- 段的一大特点就是其长度是可变的，而不是页的固定长度。从它需要处理子程序的角度出发，这是自然需要具备的特性，不然子程序长度变了咋办。并且段暴露在用户空间中，而页在内核空间；所以段能够被用户感知并使用，页对于用户来说是透明的。
- 所以段表中还需要**保存段的长度信息**

- 你可以想象编译的时候一个函数就会被创建一个段，给出入口地址就能把这玩意塞进去

### 段表映射

- 还是出于我们最本质也是最想做的事情：**应用看到的地址一定要连续！** 分段映射的地址处理也和分页处理非常类似。*由于段本质上是对页的一种抽象，我们甚至可以认为这是在对页号又进行了一次页表（虽然这不好，段不是多级页表，性质不一样，但能够辅助我们理解这一过程）*
- 对于大部分情况，我们都是把一个应用拆分成段，然后再把段分页。完成了自顶向下的过程。

- 所以我们还是能够把逻辑地址分成：**段号+页号+页内地址**的形式。唯一的不同是开头变成了段号+页号，而不是单纯的页号。而映射的最终结果应该还是**帧号+帧内地址**的形式。

![[Pasted image 20250412215732.png#pic_center|]]

- 看这张段表映射的图，虽然看起来很像将页号又页表了一次，但核心不同在于：**段号与页号是相加的，并非拼接**。这让段与页的关系变为了：**入口+偏移量** 的形式，这就实现了段能够将同一段过程映射到程序的不同地方。

- 可以把这么划分的页号也想像成一个偏移量，而段号就代表了程序真正的入口地址。那么不同的段号就意味着程序在不同的地方引用的过程。而页号这一偏移量加在段号上，保证了在这一段中程序的顺序运行，也就保证了程序行为是统一的。
- **通常段表中还需要保存一个段有多长，这样操作系统才能明确知道我们是否超出了范围，以及更多的保护措施**。

## 内存占用与分页大小的关系

- 段的大小（$S_{\text{segment}}$） **远大于**页（$S_{\text{page}}$）（好像是废话但其实不是，注意这个远大于）
- 段中的最后一页平均会浪费一半的容量
- 假设页表的每一项都是1个字，那么页表的总大小就是：$$\frac{S_{\text{segment}}}{S_{\text{page}}}$$
- 那么总内存占用就是：$$W=\frac{S_{\text{page}}}{2}+\frac{S_{\text{segment}}}{S_{\text{page}}}$$
- 求导数：$$\frac{\mathrm{d}W}{\mathrm{d}S_{\text{page}}}=\frac{1}{2}-\frac{S_{\text{segment}}}{S_{\text{page}}^2}=0\implies S_{\text{page}}=\sqrt{2S_{\text{segment}}}$$
- 物理内存中的使用率是：$$U=\frac{S_{\text{segment}}}{S_{\text{segment}}+W}$$带入$S_{\text{page}}=\sqrt{2S_{\text{segment}}}$得到：$$U=\frac{1}{1+\sqrt{\frac{2}{S_{\text{segment}}}}}$$
- 这是一个单调递增函数，随着段大小的增大越来越趋向于1

## 内存命中率和分页大小的关系

- 假设有$L$个**逻辑地址** $A_0A_1\cdots A_{L-1}$
- 假设在某个时刻，$A_i$地址被引用
- 假设在下一个时刻，$A_{i+d}$地址被引用
- 分类讨论：
	- $d$相比$S_{\text{page}}$足够小，那么$A_i$和$A_{i+d}$在同一页中的概率随着$S_{\text{page}}$的升高而升高
	- $d$相比$S_{\text{page}}$足够大，那么$A_i$和$A_{i+d}$在同一页中的概率不大；在不同的页中能够让他们同时保存在内存中，如果$A_i$和$A_{i+d}$访问都比较频繁的话，这么做是最优的。但由于分页大小增加页的数量会减小，所以此时$A_i$和$A_{i+d}$在不同页中的概率随着$S_{\text{page}}$的升高而降低。

- 最终曲线就差不多长这样

- 结论是在大型系统中理想的分页大小远大于$$S_{\text{page}}=\sqrt{2S_{\text{segment}}}$$

## Cache 映射

### 直接映射

- 最简单也是最直白的映射关系：我们希望内存地址映射到Cache地址的逻辑是唯一的，也就是说任何一个逻辑地址都有且仅有一个对应的Cache地址。
- 实现这一过程的操作为：将逻辑地址的后$n$位作为Cache的地址，称为Index，并将剩余的位数作为Tag存入Cache中以便判断是否是正确的数据。Cache的每一项包含Tag和内存本身的数据（Tag，Data）

![[Pasted image 20250413020439.png#pic_75center|直接映射的基础逻辑]]

- The **Tag** field of the **real address** is compared with the corresponding **Tag** in the **cache**. **If the two tags match**, a hit occurs.
  真实地址的Tag会与Cache中的Tag进行比较，从而确定数据是否命中
- If there is no match, the **required word (data)** is read from main memory and the cache is updated.
  如果没有命中，就会从主存中读取数据并更新Cache

- 假设Real Address有15bit，Cache的Address有9bit，那么我们能够将Real Address划分为6bit的Tag和9bit的Index.

- 在计算Cache数据的大小时，需要注意的是Cache Data一共包含Tag+Word两个部分，所以需要记得加上去。

#### Block在Cache中的存储

- 由于主存中的数据可能以Block的形式组织，我们希望Cache中的数据也能以Block的形式组织起来。
- 与书中不同的是，Gwee仍然坚持每个存储单元仅能存储1Word的理念（所以其他情况不做讨论以免混淆）

- 在之前的虚拟存储中，有一个非常重要的概念：**我们希望保证地址是连续的**。Cache也不例外，所以Real Address自然能够被分为Tag，Block和Word的形式，最后的Word保证了一个Block内的地址映射后仍然是连续的。从图上可以看到，这一切只是把Index重新划分了一下而已，更加方便进行组织。

![[Pasted image 20250413031001.png#pic_75center|处理含有Block的Cache映射]]

- 在这种组织方式中，内存会一次性向Cache传输一个Block大小的数据。如果Block内Word的传输是串行的，那么会消耗额外的时间。如果Block内Word传输是并行的，那么能够在1个Memory Cycle内完成传输，并且更大的Block容量能够提供更大的命中率（电脑运行是顺序的，所以同一Block中的数据更容易在之后的操作中命中）

	- 由于Block大小是$2^3=8$Word，所以Word地址是3bit
	- 由于Cache地址是9bit，所以剩下的6bit是Block地址
	- 由于Real Address是15bit，所以剩下的6bit是Tag

### 全相联映射

![[Pasted image 20250413042651.png#pic_50center|朴实无华的全相联映射]]

- The cache is divided into two fields, an address field and a data field.
- Each cache entry contains an address plus its corresponding data. The number of bits in the real address equals the number of bits in the cache address field.
  Real Address的位数等于Cache Address的位数，
- When a reference to memory is needed, the real address presented by the CPU is compared concurrently with all the addresses in the cache for a match.
  当有引用请求时，Cache Address会同时对输入的Real Address进行匹配

- 这种方法是朴素的全相联存储器，没有什么很特殊的。要注意的是这种映射方法不是一一对应的关系，Cache中的数据是使用算法管理的。

### 组相联映射

- 结合了直接映射和全相联映射的优势。**通过在Index相同的地方添加相联存储，来并行地匹配Tag**，从而允许了不同的Tag存储在相同的Index中。
- 回忆一下Memory Bank中的内容，有点类似。把一大块相联存储器塞进同一个地址中，让他们自己匹配内容然后输出结果。

![[Pasted image 20250413043718.png#pic_75center|2-Set组相连Cache]]

![[Pasted image 20250413044456.png#pic_75center|更加显式的表明这是一个组相联存储器]]

- When the CPU requests a memory reference, the index of the real address is used to access the cache.
  当 CPU 请求内存引用时，Real Address的Index用于访问Cache。
- The tag of the real address is then compared concurrently with all the tags in that particular entry in the cache as indicated by the index of the real address. If there is no match, a cache miss occurs and the cache will be updated by transferring a block say 8 words (if the block size is 8) from main memory containing the referenced word to the cache. Which tag-data set in that entry in the cache is to be replaced will be decided by the replacement algorithm used.
  实际地址的Tag会与Cache中该Index对应的所有Tag同时进行比较。如果没有匹配，则会发生Cache Miss，Cache将通过从Main Memory中传输一个Block（例如，块大小为8Words）来更新，该Block包含被引用的Word并被存储到Cache中。Cache中该Index对应的Tag-Data Set将被替换，取决于所使用的替换算法。
- The hit ratio will improve as the set size increases because more words with the same index but different tags can reside in cache. However, an increase in the set size increases the number of bits in each word (line or entry) of cache and requires more and complex hardware for the match logic.
  随着相联组数的提高，命中率（hit ratio）会提高，因为具有相同Index但不同Tag的更多Word可以驻留在Cache中。然而，相联组数的增加也会导致Cache中每个Word（行或条目）所需的位数增加，并需要更复杂的硬件来实现匹配逻辑。

### 读策略

![[Pasted image 20250413051019.png#pic_75center|例题中的Read-Through策略]]

- Read Through是同时从主存中读取并写入Cache的过程，在计算时只需要计算Main Memory Cycle Time（例题中有提到）

### 替换与写策略

- The replacement algorithms used for the virtual memory system are applicable to a cache-main memory system. The most popular replacement algorithms used in a cache system are FIFO and LRU.
  用于虚拟内存系统的替换算法也适用于缓存与主存系统。在缓存系统中，最常用的替换算法是FIFO和LRU。

#### Write-Through

- For every write request, the main memory is updated. This is useful when the main memory is shared by multiprocessors or for DMA.
  对于每次写请求，主存都会被更新。这在主存由多处理器共享或用于DMA非常有用。
  > DMA：直接内存访问，不需要经过CPU

- 写直达对Cache和主存同时更新。所以需要的时间是Memory Cycle Time。如果Cache Cycle Time是100nS，Main Memory Cycle Time是1000nS，那么写Cache所需要的时间是1000nS

![[Pasted image 20250413051218.png#pic_75center|例题中的Write-Through策略]]

##### Write-through-with-write allocate (WTWA)

- In this procedure, a block from the main memory containing the referenced word is loaded into cache on a write miss.
  在这种过程中，当发生Write Miss时，Main Memory中包含Referenced Word（被引用字）的一个Block会被加载到Cache中。
- 伯克利CS61C教材的内容：考虑Write-Through中的失效处理。在Cache中为其分配一个Block，被称为写分配（Write-Allocate）。将该Block从Main Memory写入Cache中，改写Block中相应部分的数据。
##### Write-through-with-no-write allocate (non WTWA)

- In this procedure, a block in the main memory containing the referenced word is not loaded into the cache for a write miss. This is generally the default procedure.
  在这种过程中，当发生Write Miss时，Main Memory中包含Referenced Word的Block不会被加载到Cache中。这通常是默认的处理方式。
- 伯克利CS61C教材的内容：直接在内存中更新对应部分的数据，并不将其写入Cache. 该策略的动机是，有时候并不需要将内存中的数据读入Cache（例如强行将某段内存初始化为0），那么在这种情况下Write-Allocate就是不必要的。

#### Write-Back

- Only the cache is updated during a write operation. The location is then marked by a metabit (a valid bit) so that the word can be identified and copied into main memory when it is to be replaced.
  在写操作期间，仅更新Cache。然后使用一个Valid Bit标记该位置，以便在需要替换时能够识别该Word并将其复制到Main Memory中。
- 在发生替换时，如果Valid Bit提示这个Word被修改过，则在替换时将这个Word写回Main Memory. 
- 问题在于使用Write-Back策略会导致Main Memory中的部分数据不可用（唯一可用的数据在Cache中），因此I/O只能通过Cache进行

- 在Write-Back策略中，进行读操作首先会把Cache中的数据写回Main Memory，然后再进行读取（Example 3），假设开启了Read-Through，那么读操作Miss的用时就应该是两倍的Block Transfer Time

## Cache初始化

- Normally, each word in cache contains a valid bit to indicate whether or not the word (or block) contains valid data. The cache is initialized by clearing all the valid bits to 0. The valid bit of a particular cache word (or block) is set to 1 the first time this word (or block) is loaded from main memory.
  通常，Cache中的每个Word都包含一个Valid Bit，用于指示该Word（或Block）是否包含有效数据。Cache在初始化时，会将所有Valid Bit清0。当某个缓存Word（或Block）首次从Main Memory加载时，其Valid Bit会被置为1。
